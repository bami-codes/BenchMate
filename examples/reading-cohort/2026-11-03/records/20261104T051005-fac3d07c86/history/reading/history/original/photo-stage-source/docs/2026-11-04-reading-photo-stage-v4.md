# Prospective candidate-set and documentary photo stages for v4 reading pairs

The numerical/reading-profile source freeze stays unchanged. This stage is
separately source-hashed and published after terminal explanation verification,
but before receiving its photo or operator value. It reuses the qualified v3
candidate parser, actual native SAM rasters/crops and the fixed RAW pipeline.

One generic SAM request localizes bodies. One Spark request receives the full
clean photo, intended schematic, all retained candidate crops/IDs and geometry.
It returns candidate IDs and kinds, then a separate nullable reference binding.
It never reads resistor bands, markings or values. Every plausible candidate is
retained when individual correspondence is ambiguous. A missing SAM body does
not establish absence. Model arguments and nullable parsing normalization stay.

An optional operator-confirmed fixture map supplies only IN/OUT/REF connector
colors and mini-board coordinates. The exact allowlist excludes component
reference assignments, numeric part values, free-form assembly instructions,
measurements and private truth. This is connector context, not a preselected
resistor label. Its artifact hash is bound before the vision request.

For a unique model proposal, operator yes/no confirmation is recorded separately
with chosen_by=muse_spark. An ambiguous candidate set pauses for a separately
qualified group-reading plan; it is not converted into an operator truth label.
Only actual retained native IDs may be used. Display derivatives show selected
candidate masks, while every original mask and unselected body remains retained.

The existing source/range-specific forecast must already be published before
photo receipt and reading. An isolated, power-off free numeric observation is
compared deterministically, without refitting. If one explanation remains, the
sealed specimen may be revealed; otherwise stop for a reading decision. A DMM
screen photo is optional. Without it, the original board picture is explicitly
context only and does not authenticate the operator-reported number.

Restored consistent diagnosis has no implicated component to locate again.
Before reading the new restored photo, record a zero-Spark/zero-value scope:
generic SAM is documentary display only, with no claimed component identity.
The repair changes the mini-board in03, so a genuinely new restored capture is
required; reused pixels are rejected. No fake restored body_binding is emitted.
The standard caption stays **No mismatch in the tests Spark chose** and native
repair/uniqueness limits remain. This omission rule was declared in03's scope
before its fresh schematic intake, not selected after viewing its photo.

`reading_timing_verify_v4` is an additive stdlib-only compound auditor. It checks
the root/child chains, every bound photograph/crop/mask/port artifact, v4/source
qualification, prediction publications and order, raw Spark candidate choice,
operator confirmation, free-number scoring, seal, restoration and documentary
omission. No key/network/solver or photo library is required for verification:

```sh
PYTHONPATH=src .venv/bin/python -S -m benchmate.reading_timing_verify_v4 <pair>
```

Numerical children still support `python -m benchmate verify <child>`. The new
pair command is explicit because the original frozen pair auditor expects a
second component binding and must not be satisfied with a fabricated one.
Hash/order verification does not prove original creation time, physical truth,
meter accuracy or unobserved waveform details. Prospective public commits supply
the separate publication-time evidence. No prior result is rewritten.
