# Prospective unchanged-mini-board photo scope

Case04's published workflow declared this before its schematic request: do not
repeat a whole-mini-board photograph/SAM/binding when only the external fault
is removed and the mini-board configuration remains the same. Keep the existing
picture's original capture scope. Record the operator's external restoration
report and subsequent physical diagnosis; infer no present wiring from old pixels.

The additive closeout implementation is frozen before case04 measurements. It
preserves all original 107 runtime files and both diagnostic and numeric reading
rules. The additive audit copies the frozen reading-pair audit and adds only the
pre-intake workflow declaration and explicitly bound `restored_photo_not_repeated`
branch. All child-chain, prediction/order, reading/publication/scoring, seal and
restoration checks remain. Tests reject a late scope, false new-photo claim or
wrong old-photo reference even when the parent chain is recomputed.

The original `python -m benchmate verify <folder>` keeps its original requirement
for photographs in both states. For these prospectively scoped pairs use
`python -m benchmate.reading_pair_closeout verify <folder>`: same one-line
PASS/FAIL and counts, standard library only, no keys or network. PASS establishes
internal hashes and recorded order, not record creation time, wiring truth or
the truth of operator assertions. Do not silently advertise the unchanged old
verifier as supporting this new completion branch.

If mini-board components/layout actually change, the original complete-photo
path remains available. The new closeout requires an actual operator report of
unchanged mini-board configuration and external-only restoration. It creates no
new photograph, model call, measurement, prediction or diagnostic outcome.
