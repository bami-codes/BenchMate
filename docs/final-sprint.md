## 실물 실행은 반드시 촬영하면서

나중에 다시 연출해서 찍을 시간이 없다. 실제 실행 원본이 "실제로 돌아간다"는 가장 강한 증거다.

- **폰 카메라:** 가로 화면, 1080p 또는 4K, 30fps. 브레드보드와 아두이노가 다 들어오게
  책 더미 위에 폰을 올려 45° 각도로 내려다보게 둔다. 화면을 길게 눌러 초점·노출을 고정(AE/AF 잠금)하고,
  스탠드 조명을 켠다. 책상 위의 다른 물건과 얼굴, 개인정보는 화면 밖으로 치운다.
- **꼭 찍어야 하는 순간:** Spark가 부하를 요청했을 때 E30–A55 점퍼를 꽂는 손,
  예측이 푸시된 뒤 추가 C(I8–I13)를 빼는 손, USB를 다시 꽂고 측정이 도는 장면.
  작업 중에는 녹화를 끊지 않는다.
- **화면 녹화:** 맥에서 Cmd+Shift+5로 전체 화면을 녹화한다. 가능하면 `benchmate watch` 라이브 뷰어를 띄우고,
  안 되면 실행기 터미널을 띄운다. Codex는 watch가 수리 실행 로그를 보여줄 수 있는지 먼저 확인한다.
- 원본 영상은 `video/raw/`에 넣는다(git에 커밋하지 않는다. `.gitignore`에 추가).

## Claude 작업 기록

- **11/1 18:40 수리 Story 화면 완료 (커밋 대기).** `benchmate view`와 `benchmate watch`가 이제 D01 수리 실행
  (`meta_d01_repair_physical`, `scripted_d01_repair_mock`)을 보여준다. 진단 → 수리 예측 고정·공개(해시, 커밋 링크) →
  작업자 수리 → 수리 후 두 검사(Repaired / Not repaired 곡선)까지 나온다. mock은 "Mock bench · rehearsal", "Scripted decision"으로 표시한다.
  변경 파일은 `src/benchmate/viewer.{py,js,css,html}`, `viewer_physical.js`, 새 테스트 `tests/test_repair_viewer.py`다.
  뷰어 테스트 17개가 통과했고, 기존 D01 진단 화면은 바뀌지 않았다.
  전체 테스트에서 3 failed / 7 errors가 나오지만, 변경 전 코드에서도 똑같이 나온다(ngspice 없음, Pillow 버전 차이 때문이고 이번 변경과는 무관).
- **Spark의 한국어 이유를 영어로 표시:** 실행 폴더에 `translations.json`을 두면 Story에서 영어 번역을 보여준다.
  항목마다 `event_sequence`, `event_sha256`, `field`(예: `reason`), `original`(원문 그대로), `english`가 필요하다.
  해시나 원문이 맞지 않으면 뷰어가 로드를 거부한다. 번역은 실물 실행이 끝난 뒤 Claude가 만든다.
- **실물 수리 실행 중에는 라이브 화면을 녹화한다:** 실행기가 실행 폴더를 만들면
  `uv run benchmate watch <실행 폴더> --port 8765`를 띄우고 브라우저에서 `http://127.0.0.1:8765`를 연다. 그 화면을 Cmd+Shift+5로 녹화한다.
