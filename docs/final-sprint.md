## 실물 실행은 반드시 촬영하면서

나중에 다시 연출해서 찍을 시간이 없다. 실제 실행 원본이 "실제로 돌아간다"는 가장 강한 증거다.

- **폰 카메라:** 가로 화면, 1080p 또는 4K, 30fps. 브레드보드와 아두이노가 다 들어오게
  책 더미 위에 폰을 올려 45° 각도로 내려다보게 둔다. 화면을 길게 눌러 초점·노출을 고정(AE/AF 잠금)하고,
  스탠드 조명을 켠다. 책상 위의 다른 물건과 얼굴, 개인정보는 화면 밖으로 치운다.
- **꼭 찍어야 하는 순간:** Spark가 부하를 요청했을 때 E30–A55 점퍼를 꽂는 손,
  예측이 푸시된 뒤 추가 C(I8–I13)를 빼는 손, USB를 다시 꽂고 측정이 도는 장면.
  작업 중에는 녹화를 끊지 않는다.
- **화면 녹화:** 맥에서 Cmd+Shift+5로 전체 화면을 녹화한다. 가능하면 `benchmate watch` 라이브 뷰어를 띄우고,
  안 되면 실행기 터미널을 띄운다. Codex는 watch가 수리 실행 로그를 보여줄 수 있는지 먼저 확인한다.
- 원본 영상은 `video/raw/`에 넣는다(git에 커밋하지 않는다. `.gitignore`에 추가).

이 검토는 배선 변경 요청이나 새 실물 결과가 아니다. D01 준비·설계 확인은 아직
사용자 답변을 기다리는 상태이며 새 Spark 지휘 실물 수리 기록은 없다.

### 원문과 주장 수정

- 포럼 12·20번에는 입력 클램프/전원 여부에 관한 설명이 이미 있다. 46번(7/17)은
  질문자가 전원 유무에 따른 분압 전압 차이를 시험해 보고한 글이다. 인용하려는
  실물 시험에 관한 결론 문장은 46번이 아니라 **57번(7/25)** 에 있다.
- 첫 글과 확인 보고 사이의 경과일을 실제 디버깅 노동시간으로 간주하지 않는다.
  59개 글에는 해결 확인 이후의 논쟁도 포함된다. ‘엿새 내내 추측만’, ‘아무도
  몰랐다’, ‘Six days on a forum, N minutes on a bench’는 사용하지 않는다.
  우리 단순화 시편은 같은 난도의 같은 문제를 독립적으로 푼 시간 비교가 아니다.
- B5는 이 사례에서 영감을 받은 **단순화한 입력 클램프 시험 회로**다. 실제 ESP32나
  원문 PCB를 사용하지 않는다. 원문의 100kΩ/100kΩ 분압기는 테브난 저항 50kΩ인데
  현재 B5는 10kΩ이고, 칩의 내부 전원 레일·부하도 재현하지 않는다. 전압이 다르다는
  작은 자막만으로 ‘Now the forum circuit, rebuilt’나 ‘It is the ESP32’s input
  protection’라는 주장을 보완할 수 없다. 비슷한 동작을 보이는 모델은 내부 부품의
  위치나 유일한 원인까지 식별하지 못한다.
- B5에서 ‘처음 다섯 선형 후보에는 없던 다이오드 구조’라고 말할 수 있다. 도구
  명세에는 처음부터 R/C/D 부품이 허용돼 있으므로 ‘아무 힌트도 없다’는 문구는
  ‘시편의 실제 배선을 알려주지 않았다’로 바꾼다.
- 현재 완료된 것은 기존 실물 D01 진단과 별도 스크립트 수리 점검이다. 새 Spark
  실물 수리는 아직이다. story-v3 첫 단락의 수리 완료 표현과 장면 4의 성공 문장은
  실제 새 기록이 생길 때까지 예정으로 표시한다. 도구 없는 다섯 답변의 재측정
  권고도 함께 보여준다. C 추정에는 명목 R을 가정했다는 짧은 표시를 유지한다.

### 전원 레일 전환: 가능 여부와 개발 견적

다이오드 캐소드 전위를 충분히 높이면 이 신호 범위에서 클램프가 꺼져 OUT이 IN을
따를 것이라는 **단순화 회로의 정성적 예상**은 타당하다. 하지만 이것은 실제 칩에
전원을 넣는 실험이 아니며, 현재 B5에 점퍼 하나만 추가해서 검증 완료로 셀 수 없다.

현재 도구/넷리스트에는 별도 구동 RAIL 단자가 없고 R/C/D 수동 소자만 허용한다.
학습과 예약 검증은 같은 boot_id·origin_id를 요구한다. 따라서 새 외부 레일을
넣고 USB를 다시 연결하는 단계는 다음 작업을 갖는 **별도 사후 개입 프로토콜**이다.

1. 고정된 레일 개입용 시뮬레이터 구성과 전압 범위 검토. 모델이 임의 전원 명령을
   만들도록 도구를 넓히지 않는다.
2. 학습에서 섞여 추정되는 R·IS·REF와 새 부팅의 원점/출력 차이 처리. 이전 모델의
   임시 바이어스를 새 부팅에 그대로 옮겨 9mV 성공을 가정하지 않는다. 새 평가 OUT으로
   다시 맞추지 않는 비교 규칙을 먼저 정한다.
3. 두 레일 상태의 예측 선공개, 새 부팅 검사, 정확한 USB-off 작업자 확인,
   실패 시 중단과 전원 레일 연결 검사. REF와 3V3가 함께 연결되지 않도록 한다.
4. API·실측·기록 및 영상의 설명 범위 검토. 실제 칩 전원 복원으로 표현하지 않는다.

코드를 읽고 산정한 견적은 **구현·모의 검증 2–4시간 + 실물 점검 30–60분 이상**이다.
통신/전원/보정 문제 해결 시간은 별도이며 완료 보장이 아니다. 현재는 D01 수리와
기존 B5 실물 검증을 먼저 확보한다. 둘을 마친 뒤에도 시간이 충분할 때만 다시
판단하며, 월요일 18시 제한과 B5 3시간/2회 및 전체 23시 동결을 늘리지 않는다.
지금은 기존 D8–D13 다이오드 준비 절차를 변경하지 않는다.

## B5 변형 선정 종료

고정한 계산 예산으로 진행한 선정 작업은 종료했다. 한도는 맞추기 사이에 검사하므로
마지막 맞추기의 종료만큼 초과할 수 있으며 실제 경과 시간은 원문에 남겼다. 등록 13개 중 5개에 선정 분류가
남았고, 나머지는 `selection_incomplete`로 보존했다. 주 평가에 선정된 변형은 **0개**다.
선정 규칙·후보·난수·실행기 코드는 도중에 바꾸지 않았고, 맞추기 실패를 대안 탈락으로
세지 않았다. 실제 Spark 최종 평가는 실행하지 않았다.
[전체 선정 결과](../examples/b5-variants/2026-11-02/SELECTION.md)와 원문을 푸시했다.

이 결과에는 정확도 X/N을 붙일 수 없다. 0%나 100%로 표시하지 않고, 이번 영상의
넓은 구조 발견 성능표는 제외한다. 실물 D01 수리와 B5 실행에 시간을 우선 쓴다.
