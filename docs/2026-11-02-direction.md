## 사례: 포럼 문제를 축소한 회로

계측 장치(큰 보드, 아두이노, LM358, 기준 전압)는 그대로 둔다. 사례마다 미니 브레드보드의 시험 회로만 바꾼다.
회로도는 사례마다 두 장이다. 둘 다 Claude가 그린다.

- **설계 회로도 (Spark가 진단 전에 읽는 것)**: 미니보드에 올린 부분만 IN/OUT/REF 단자로 그린다.
  앞뒤는 "Source", "Next stage" 같은 이름 없는 상자로만 둔다. 칩 이름, 보드 이름, 숨은 내부 구조(핀 저항, 보호 다이오드 등)는 넣지 않는다.
  Spark가 이 이미지를 읽어 설계값을 뽑고 범수가 확인한다(기존 회로도 판독과 확인 흐름). 실행 기록에는 Spark가 받은 이미지 파일을 남긴다.
- **이야기 회로도 (사이트용)**: 원래 상황 전체를 그린다. 벤치에 없는 부분(칩, 센서 보드 등)은 회색 상자로, 미니보드에 올린 부분은 진하게 그린다.
  숨은 내부 구조는 정답 공개 뒤에만 보여준다. Spark에는 주지 않는다.

| 사례 | 근거 (원인 확인 여부) | 원래 상황 | 숨긴 고장 | 사진에 보이나 |
|---|---|---|---|---|
| 핀 출력 저항 | [Arduino 1098926](https://forum.arduino.cc/t/oscilloscope-low-pass-filter-help/1098926), 확인됨: 핀 출력 저항 약 40Ω이 직렬 R에 더해짐 | 아두이노 핀 → RC 필터 → 스코프 | 미니보드 밖 직렬 R (IN 측정점과 R1 사이) | 안 보임 |
| 값이 틀린 커패시터 | [Arduino 380339 GY-521](https://forum.arduino.cc/t/mpu6050-breakout-board-gy-521-wrong-capacitor-results-in-erratic-data/380339), 확인됨: 100 nF 자리에 약 2 nF. 다른 사용자가 교체해 해결 | 레귤레이터 → 필터 C | 105 자리에 474 | 표시를 읽으면 보임 |

| 접촉 저항 | [EEVblog](https://eevblog.com/forum/beginners/voltage-drop-at-breadboard), 반쯤: 납땜하자 정상. 점퍼 탓인지 접촉 탓인지는 못 가림 | 브레드보드·점퍼 연결 | 미니보드 밖 직렬 R | 안 보임 |
| 다음 단 입력 용량 | 포럼 확인 사례 없음. "알려진 부작용(대조군)"으로만 표시 | 분압·필터 → 다음 단 입력 | 미니보드 밖 OUT C | 안 보임 |
| D01 | 우리가 심은 결함(대조군) | 10kΩ·1µF RC | 미니보드 병렬 C | 보임 |
| 꺼진 칩의 보호 다이오드 (별도) | [Arduino 884099](https://forum.arduino.cc/t/voltage-divider-is-not-giving-correct-voltage/884099?page=3), 확인됨: 46번 재시험, 57번 결론 | 배터리 → 분압 → 꺼진 ESP32 핀 | 미니보드 밖 다이오드 | 안 보임 |

- 다이오드는 ±0.2V 스텝으로는 거의 켜지지 않는다. 그래서 같은 D01 절차에 넣지 않고 B5로 따로, 끝나는 시각을 정해 한 번 시도한다.
- 각 사례는 수리한 뒤 다시 돌린다. 그 재실행이 정상 대조군이다. Spark는 실행마다 기억이 없으므로 공정하다.
- 사례 페이지마다 세 줄을 넣는다. Kept(원인 구조), Changed(값 축소, 칩은 회색 상자), Source(원문 링크).
  "그 사람 보드를 고쳤다"가 아니라 "같은 원리를 우리 벤치에서 재현"이라고 쓴다.
- 인용은 원문을 직접 열어 확인한 문장만 쓴다.

## 정직성 규칙

- **같은 절차**: 모든 사례에 같은 절차를 쓴다. 사례별로 실행기를 고르면 그게 정답 누설이다. 회로도에서 읽은 설계값만 달라진다.
- **사진은 진단 뒤에만**: 사진은 Spark 진단에 넣지 않는다. 진단 뒤에 공개해서 "이 부품" 안내와 회로도 대조에만 쓴다.
  사진 판정과 측정 판정은 서로 보지 않고 따로 기록한다. 어떤 고장도 "사진으로 안 보임"으로 미리 판정하지 않는다.
- **파일럿과 본시험 구분**: 파일럿은 마음껏 돌리고 고친다. "pilot"으로 표시하고 집계에서 뺀다.
  안정되면 사례 목록, 판정 규칙(종류, 크기 허용 범위, 정상에서 잘못 울린 경보), "고정 뒤 실행은 전부 집계"를 커밋하고 본시험을 시작한다.
- **데모 실행**: 본시험 중 가장 잘된 실행을 대표 화면으로 쓰되 "demo run"으로 표시한다.
- **언어**: Spark 프롬프트, 작업자 지시문, 보고 문장을 영어로 바꾼다.
  지금은 agent.py, d01_repair.py, physical_rc.py, providers.py에 "in Korean" 지시가 있고,
  physical_d01_repair.py, physical_spark_rc.py, b5_unloaded.py의 지시문이 한국어다.
  영어판은 첫 실물 실행 전에 고정하고 amendment를 남긴다. 10/30 기록과 기존 벤치마크는 그대로 두고, 한국어 이유 문장으로 돌렸다고 표기한다.
- **다시 돌리지 않을 것**: 과제 B(Spark 15/16, 무작위 30/48, 고정 절차 16/16)와 Spark Open 과제 A(21/24)는 이미 있다.

## Claude 코드 확인 결과 (11/2 21:35, 692c590 기준)

- **값이 10kΩ·1µF로 고정돼 있다.**
  - `physical_rc.py`: 프롬프트("R=10 kohm, C=1 uF"), `train_unloaded`의 세 모델, `snapshot`의 `nominal_design`, 부하 9990Ω이 전부 상수다.
  - `d01_repair.py`의 `reviewed_design()`은 다른 값이면 "This frozen repair fixture supports reviewed 10 kohm / 1 uF only"로 거부한다.
  - 사례마다 다른 값을 쓰려면 이 상수를 확인된 설계값으로 받게 바꿔야 한다. 영어 전환과 함께 새 버전 하나로 고정한다.
- **측정 가능한 τ**: 첫 스텝에서 τ를 2–80 ms 범위에서 맞추고, 경계 1% 안이면 실패 처리한다. 스텝은 0.5 ms 간격 512점(256 ms)이다.
  정상과 고장 상태 모두 대략 3–70 ms 안에 들어오게 값을 잡는다. 555의 10배 축소는 설계 τ를 위쪽(약 60 ms)에 두어야 가능하고, 3–5배가 안전하다.
- **부하**: 9.99kΩ 하나로 고정이다. 설계 R이 10k에서 멀어지면(예: 68k) 부하를 건 출력이 작아져 9 mV 판정이 빡빡해진다. 설계 R은 4.7k–22k 안을 권한다.
- **회로 모양**
  - D01 진단 절차의 가설은 RC 저역통과의 세 가지(설계 그대로, R 변화, C 변화)뿐이다.
  - 분압기(`resistor_output_leak`)는 B5 탐색 절차의 시작 후보 다섯 개 안에만 있다. B5는 설계를 모르는 상태에서 구조를 찾는 다른 절차다.
  - 고역통과는 두 절차 어디에도 시작 후보로 없다.
  - 그래서 같은 절차로 묶이는 사례는 RC 저역통과(값만 다름)이고, 모양이 다른 사례는 884099(B5) 하나다.
- **정상 시편**: τ가 설계와 같으면 R 변화 모델과 C 변화 모델이 설계 모델과 같은 곡선이 된다.
  그러면 하나만 남는 후보가 없어서 검증을 못 하고 Spark는 abstain한다.
  판정 규칙에 "τ가 설계와 맞고 R·C 변화를 주장하지 않은 abstain = 정상 판정"을 넣거나, 이런 경우 "설계와 일치"로 보고하는 작은 코드 변경이 필요하다.
- **수리**: 구현된 수리는 C 복원(`restore_nominal_capacitance`)뿐이다.
  R 고장 사례는 범수가 부품을 바로잡은 뒤 진단을 다시 돌리는 것으로 정상 확인을 한다. 그 재실행이 대조군이다.
- **보드 밖 고장 위치**: 숨긴 R은 큰 보드의 IN 측정 지점과 미니보드 IN(A3) 사이 연결선에, 보드 밖 C는 큰 보드의 OUT(E30)과 REF(D50) 사이에 둔다.
  정확한 구멍은 Codex가 배선표로 확정한다.
