# LED 포함 넷리스트 진단 v2

11/2 Codex. 사용자가 LED도 지금 합치기로 했고, 실제 부품을 **JCET BC547B
(BC547 / B GLG, bent lead)**와 **빨간색 5 mm 평면형 확산 LED**로 확인했다.

**여섯 포럼 사례가 하나의 소프트웨어 실행기에 포함된다.**
여섯 실물 사례 완료, 실제 Spark 선택, 사진 판독 완료를 뜻하지 않는다.
이 구현 중 유료 요청, 실제 USB/시리얼, 배선, 펌웨어 업로드는 전부 0회다.

## 이번에 추가한 것

- `src/benchmate/netlist_diagnosis_v2/`와 `scripts/netlist_diagnosis_v2.py`를 추가했다.
  v1 런타임 66개 파일은 바꾸지 않았다.
- 기존 다섯 회로는 v1의 수치 엔진과 구조 제안을 재사용한다.
  LED는 실제 NPN과 다이오드를 ngspice에 넣는 별도 active profile이다.
  고정한 네 부품 연결 범위이며 임의 능동 회로 구조 탐색까지 지원하지 않는다.
- 여섯 사례 모두 동일한 훈련 메뉴, 최대 세 번의 선택, 같은 예약 입력 두 개,
  동일한 영어 도구 흐름과 전체/구간 9 mV 기준을 쓴다.
  실제 Spark 실행에서는 Spark가 각 실험을 고른다. 무료 검증만 명시적인 시험용 제어기를 쓴다.
- LED에서도 모델·매개변수·명령 입력 예측을 예약 측정 전에 동결하고 공개 확인한다.
  예약 OUT으로 다시 맞추거나 실패 뒤 재시도하지 않는다.

## LED의 네 부품과 측정 경로

| 요소 | 의도 회로 | 역할 |
| --- | --- | --- |
| Rbase | 4.7 kΩ, IN–BASE | 정상 베이스 구동 |
| Rled | 1 kΩ, 5V–LED 애노드 | 낮은 전류의 LED 부하 |
| D1 | 빨간 LED, 애노드–COL | 광출력 대신 시뮬레이션 전류를 개발 점검에 사용 |
| Q1 | BC547B, C=COL / B=BASE / E=GND | NPN 스위치 |

고장 개발값은 Rbase=1 MΩ다. 수리 대조군은 4.7 kΩ로 복원한 **새 세션**이다.
원글의 다섯 LED·약 100 mA·4.7 kΩ→470 Ω를 그대로 사용하지 않는다.
LED 하나의 낮은 전류에서는 원문의 4.7 kΩ도 충분할 수 있어, 고장값을 크게 잡았다.
이 축소와 변경을 사례 페이지의 Changed에 명시한다.

**COL과 측정 OUT은 서로 다른 노드다.** 제안하는 계측 어댑터는 큰 보드 쪽의
COL–47 kΩ–OUT, OUT–10 kΩ–REF다. 출력 부하 9.99 kΩ을 선택하면 OUT–REF에
추가되며, 그 부하가 분압 비율을 바꾸는 효과도 모델에 포함한다.
이 두 저항은 미니보드의 네 시험 부품과 별도로, 알려진 계측 경로다.

5V와 **GND**가 모두 필요하고 기존 REF는 약 1.6 V 기준점으로 유지한다.
Q1 이미터를 REF에 연결하지 않는다. 실물 핀 방향·빈 구멍·추가 선은 아직 확인하거나 지시하지 않았다.
위 표는 설계·시뮬레이션 명세이며 지금 연결하라는 작업 지시가 아니다.

현재 모델의 정상·고장, BF=200/450, 빨간 LED의 개발 Vf 범위 양 끝을 검사했을 때
알려진 어댑터를 통과한 OUT은 기존 신호 범위에 들어왔다. 시뮬레이션의 공급 전류는
5 mA, 베이스 구동 전류는 3 mA를 넘으면 거부한다.
**이 설계에서는 기존 전압 한도를 넓히거나 펌웨어를 새로 업로드할 필요가 없다.**
아날로그 측정 경로 자체가 그 조건을 만족하도록 한 제안이며, 실물 교정은 아직 필요하다.

LM358은 5V에서 전원 상단까지 정상적으로 측정/출력하는 rail-to-rail 부품이 아니다.
그래서 컬렉터를 그대로 기존 입력에 넣는 방법 대신 감쇠한 OUT을 사용한다.
[ST LM358 데이터시트](https://www.st.com/resource/en/datasheet/lm358.pdf).

## 값과 소자 불확실성

[JCET 작성 데이터시트](https://aitendo3.sakura.ne.jp/aitendo_data/product_img/transisitor/JCET/BC548_JCET.pdf)의
B 등급은 지정 시험 조건에서 hFE 200–450이다. 이 범위를 모델의 건강한 BF nuisance 범위로
사용하지만, BF가 실제 소자의 모든 전류·전압에서 측정된 hFE라는 뜻은 아니다.
이 소자는 특성 측정을 하지 않았고, 완전한 제조사 SPICE 모델을 얻었다고 주장하지 않는다.

빨간 LED의 1 mA 부근 Vf는 개발용 1.7–2.3 V 범위로 둔다. LED의 정확한 품번·특성 곡선은
아직 없으므로 이는 데이터시트 보증값이 아니다. 접합 용량을 생략한 저주파 모델이다.
훈련에는 정상 설계, Rbase 변화, Rled 변화, LED 특성 변화, Q1 이득 변화 가설을 넣는다.
각 가설은 같은 건강한 소자 불확실성을 공유하며, 자기 부품의 허용 범위만 넓힌다.

첫 결과는 **Rbase 증가와 Q1 저이득이 구분 불가**였다. 큰 저항과 매우 낮은 이득이
공통 메뉴와 예약 입력에서 거의 같은 OUT을 만든다. 그래서 Rbase만 고장이라고 확정하거나
유일한 저항값을 얻었다고 하지 않는다. 사진의 색띠 판독은 이 후보 집합을 별도로 좁힐 수 있다.
LED가 켜졌거나 실제로 어두워졌다는 광학 측정도 하지 않았다.

## 재현

```sh
.venv/bin/python scripts/netlist_diagnosis_v2.py catalogue
.venv/bin/python scripts/netlist_diagnosis_v2.py run-mock --case dim-led --output runs/NEW_LED_DIRECTORY
.venv/bin/python scripts/netlist_diagnosis_v2.py evaluate --output runs/NEW_SIX_CASE_DIRECTORY
.venv/bin/python -m pytest -q tests/test_netlist_diagnosis_v2.py
```

기본 실행은 유료/물리 요청이 없는 scripted mock이다. 기록과 프롬프트에 이 구분을 남긴다.
정상과 고장 모델을 같은 ngspice가 계산한 개발 검사라서 정확도 평가로 쓰지 않는다.
별도 검사는 SPICE를 쓰지 않는 Ebers–Moll/LED 방정식을 풀어 네 가지 정상·고장/부하 조건과 대조한다.

현재 구현의 핵심 보존·예측·예약 검증 검사 15개가 통과했다.
전체 여섯 회로의 고장/복원 기록과 출처는 [v2 개발 기록](../examples/netlist-diagnosis-v2/2026-11-02/REPORT.md)에 둔다.

## 실물 전 남는 조건

LED는 출력의 DC 바이어스를 보존해야 한다. v1의 별도 OUT HOLD 원점을 빼면 고장 정보를
없앨 수 있으므로 그 경로를 쓰지 않는다. 독립적으로 확인한 REF와 A2의 DC 교정,
실제 공급 전압, 두 측정 저항의 값/로딩, 정지 구간 검사와 배선 확인이 먼저 필요하다.
그래서 현재 v2는 **LED 물리 실행을 코드에서 차단**한다. 준비 파일도 실행 승인이 아니다.

이 사용자가 확인한 부품은 준비됐지만, 실제 전원·GND·감쇠 경로 연결과 계측에는 별도 승인이 필요하다.
실물 준비 시에는 먼저 요청할 API 호출 수·비용과 하드웨어 동작 범위를 제시한다.
