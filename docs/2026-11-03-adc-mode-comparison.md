# ADC 읽기 방식 대조 — 실행 전 준비

## 점퍼 교체 후 자동 QA 결과

사용자의 “완료” 보고 뒤, 새 부팅 `a65c15bbe82e1cbe9a9f4f8c6620f74d`에서 한 번 ARM했다.
HOLD 3개, ±0.2 V STEP 및 복귀 HOLD는 기존 가드를 통과했다. 다음 ±0.5 V STEP에서
A4 블록 평균 범위 3.369 mV로 기존 3 mV 한도를 넘어 중단했다. 6블록/3072프레임이다.
큰 스텝의 음→양 정상 구간 차이는 A3=7.983 mV, A4=7.954 mV다. 마지막 파형 응답과 PING은
REF/1376 복귀를 보고했다. 원시 실패 결과의 보수적인 output_state_confirmed:false도 그대로 보존한다.
점퍼 교체만으로 해결되지 않았으며 진단·예약 검증·집계에 사용하지 않는다. 추가 Spark는 0회다.

## 설치된 코어에서 확인한 동작

Renesas UNO 코어 1.6.0의 `cores/arduino/analog.cpp`에 있는 `adcConvert`는 scan_mask를 OR로
누적한다. 초기화 때 A1–A4를 모두 읽었으므로, 함수 호출 순서와 실제 하드웨어 내부 변환 순서를
같다고 볼 수 없다. 과거 52/105/158/215 µs 값은 반환 완료 시각이며 채널별 샘플링 순간이 아니다.
이 코드 확인은 ADC가 현재 오차의 원인이라는 확정이 아니다.

## 별도 시험 버전과 고정 대조

원본 firmware/instrument와 실행 소스 76개는 수정하지 않는다. 별도 instrument_adcqa는
프로토콜 이름이 다르므로 기존 진단 실행기가 거부한다. 원래 DAC·부팅·ARM·DC·중단 경계를
유지하며, ADC 읽기 모드만 추가한다. 모드 변경은 같은 부팅의 무장된 REF 출력 상태에서만 된다.

| 모드 | 읽기 방식 |
|---|---|
| 0 | 설치된 코어의 기존 analogRead |
| 1 | ADC가 정지한 상태에서 ADANSA 두 레지스터로 채널 하나를 명시 선택하고 한 번 변환 |
| 2 | 모드 1과 같은 채널을 두 번 변환하며 첫 값을 버림 |

실제 ADC 선택/데이터/시작 비트는 설치된 공식 RA4M1 CMSIS 헤더의 ADANSA[2], ADDR[28],
ADCSR.ADST 정의를 사용한다. 모드 1·2는 두 선택 레지스터를 매번 설정·확인한다.
변환 대기 1 ms 초과나 잘못된 결과는 오류로 고정하고 다음 동작을 중단한다.
사용 채널의 기존 255 샘플 상태도 취득 전후 확인한다. 임의 순서·샘플 시간 변경은 하지 않는다.

대조 순서는 0→1→2→0이다. 각 모드에서 HOLD×3, 작은 STEP, 복귀 HOLD, 큰 STEP, 복귀 HOLD를
취득한다. HOLD는 512/2 ms, STEP은 512/500 µs·명목 진폭 ±0.2 V와 ±0.5 V다. 총 최대 28블록이다.
실제 완료 시각과 프레임 간격을 기록하며, 과거의 A2=105 µs를 새 방식에 강제로 적용하지 않는다.
원시 패킷은 수정 없이 보존한다. 호스트의 명시적 메타데이터 변환은 기존 행·부팅 검사의
재사용만을 위한 것이며, 새 읽기 완료 시각을 실제 샘플링 순간으로 취급하지 않는다.

3 mV 기준은 그대로다. 초과는 전부 실패로 표시하되, 이번 정비 대조에서는 전기적 범위 안에서
계획된 모드를 비교한다. 레일·전압 범위·정적 경로 간 차이·타이밍·통신·부팅·ADC 오류는 즉시
중단한다. 실패 자료를 진단 합격으로 바꾸거나, 여기서 보정 계수를 맞추지 않는다.

## 실행 승인 범위

준비는 실제 하드웨어를 사용하지 않는다. 실행에는 사용자의 별도 승인을 받는다.
승인할 구체적 작업은 시험 펌웨어 업로드 1회, 현재 무부하 DUT 배선에서 위 자동 대조,
시험 종료 후 원본 펌웨어 복원 1회다. Spark/API는 0회·$0이다. 자동 취득은 약 2–3분 예상이며
업로드와 결과 분석은 별도다. 사용자의 추가 수동 mV 판독은 필요하지 않다.

승인 전 업로드·ARM·CAPTURE를 보내지 않는다. 업로드와 자동 취득을 재시도하지 않는다.
원본 복원은 승인 범위에 포함된 별도 정리 작업이다. 원복 후에는 새 부팅·비무장 상태를 확인한다.
새 방식이 좋아도 기존 파일럿이나 프로토콜에 자동 적용하지 않는다. 채택은 새 amendment와
읽기 시각·물리 검증을 별도로 고정해야 한다.
