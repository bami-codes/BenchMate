# Claude에게: 11/2 미커밋 변경 검토 요청

Codex 검토, 기준 HEAD `692c590`. 기준 방향은 [11/2 밤 결정](2026-11-02-direction.md).

## P1: 저장 질문 드롭다운 삭제 후 화면 초기화 중단

`src/benchmate/case_review/index.html`에서 `case-picker`를 삭제했지만 `app.js`는 다음 참조를 유지한다.

- 153–156행 `refreshLibrary()`의 `replaceChildren/add/value`
- 163행 `showAsk()`의 `.value`
- 191행 `openCase()`의 `.value`
- **976행** 최상위 `addEventListener`

실제 HTML ID 목록으로 DOM 조회를 구성해 전체 app.js를 실행하면 다음 오류가 난다.

```text
app.js:976
$('case-picker').addEventListener(...)
TypeError: Cannot read properties of null (reading 'addEventListener')
```

이 지점 뒤의 사진 이벤트와 초기 라우팅도 실행되지 않는다. 이벤트 등록만 막아도
refreshLibrary/openCase/showAsk의 null 접근이 남으므로 삭제된 UI의 참조를 모두 정리해 달라.
새 방향에서 질문 입력창 자체를 본문에서 빼기로 했으니, 공개 사례 진입 경로도 함께 맞춰 달라.

검증 요청: 전체 스크립트 시작, 사례 직접 URL, 재생, 사례 전환/돌아가기, 사진 열기.
`tests/test_case_ui.cjs`는 wiring 앞까지만 실행하고 없는 ID에도 가짜 노드를 만들어
현재 7개가 모두 통과한다. 실제 HTML에 없는 요소는 null을 반환하는 시작 검사도 필요하다.
Codex는 이번에 failing test를 커밋하거나 소유 파일을 대신 고치지 않았다.

## Codex 실행 결과와 새 회로도 인계

화면 3파일과 JS 검사를 `0901b4e`로 커밋·푸시했다. 실제 HTML ID를 사용하는 전체 시작과
새 질문으로 돌아가기 검사, 기존 JS 7개 검사에 통과했다. 화면 파일은 Codex가 고치지 않았다.

이전 A안 부품값 대신 [넷리스트 진단 v1의 연결표](netlist-diagnosis-v1.md)를 사용해 달라.
센서 필터의 두 C는 최신 사진 지침에 맞춰 OUT–REF 병렬로 정했다. 다만 1 µF→0.47 µF의
큰 감소는 0.1 µF 바이패스 하나의 감소로 설명할 수 없어, 현재 한 부품 고장 가정에서는 측정으로
Cfilter를 좁힌다. "사진 없이는 반드시 둘을 구분하지 못함"으로 쓰지 않는다.
555의 RA/RB는 실제로 구분 불가 결과가 나왔다. 두 값은 각각 10 kΩ이며 하나만 2.2 kΩ로 바꾼다.
실제 555 없이 타이밍 사슬을 재현한 점, 원문은 두 저항이 틀렸다는 차이를 Changed에 쓴다.

정상 접촉 회로는 IN과 OUT이 같은 선으로 연결되고 R/C가 병렬이다. 회로도에서도 그 연결을
분명히 보여 달라. 새 확인 파일은 그 선을 W1으로 나타낸다. 숨긴 직렬 R은 모델 이미지에 넣지 않는다.
LED는 BC547과 LED가 있는 것으로 사용자가 확인했으며, 별도 4–8시간 범위로 남아 있다.
