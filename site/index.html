    The bench

    A $40 bench the model never touches: one Arduino, one instrument board, and the mini board with the circuit from the drawing plus one sealed fault.

    Who does what

    1. Muse Sparkasks for the next experiment, and says why.
    2. Arduinoruns it, and records the input, the output and the bench's own reference.
    3. Operator when askedmoves one jumper, or reads one part with a multimeter. Never tells the model the fault.

    The bench's own rules

    • A fixed menu. Steps and sines, with or without a load. Spark chooses from it; it cannot invent a new instrument.
    • Forecast before measuring. Every forecast is simulated and hashed before the bench moves.
    • It checks itself. The bench watches its own reference on every capture and stops the run if it drifts.
    For engineers: signal chain and numbers
    Source
    UNO R4 DAC → LM358 follower → 1 kΩ. Steps ±0.2 / ±0.5 V, sines 1–5 Hz, from a fixed menu.
    Recorder
    14-bit ADC: IN, buffered OUT, REF. 512 frames per capture; the sample period is set per experiment (0.5, 2 or 4 ms in the counted runs). Captures are bound to a boot id.
    Reference
    Buffered 1.63 V, not ground. Drift above 3 mV on any capture stops the run.
    Allowance
    9 mV RMS, whole step and every region. Frozen before the first run, never changed.
    Operator
    Moves the 9.99 kΩ load jumper and reads one part, only when Spark asks. Never tells the model the fault.
    Cost
    About ₩56,000 ($40) of parts, plus a multimeter. Build notes.

    Why this matters

    The first power-on of a new board, when the output is not what the drawing says. The question at the bench is what to measure next, and which part to check.

    • Muse Sparkchooses each experiment from the fixed menu, reads the misses, proposes new circuit structure when every value explanation has failed, and asks for a reading when the waveforms cannot decide.
    • ngspice and the enginedo the numerical fitting, the waveform forecasts, the miss against the 9 mV allowance and the rule-out. Every forecast is hashed before the bench moves.
    • SAM 3.1 and Spark visionsay which body on the board photo is which part, after the diagnosis. No value is read from a photo.
    • The operatormoves the jumper and reads the multimeter when asked, and never tells the model the fault.

    The rule for all four: say what to expect before the measurement, be held to it by code, keep going until one explanation is left. That shows where the model contributed. It is not evidence that the model beats every rule-based method: on the earlier synthetic linear benchmark, an engine with a fixed plan reached the same count (development results).

    The loop needs six things and none of them is electronic — a description of what was intended, explanations the model may propose, a simulator, an instrument with a fixed menu, a person for what the instrument cannot do, a sealed truth — so the same loop could run on a real PCB at first power-on, a thermal rig or a lab experiment. Not done here: the 9 mV allowance, the menu and the calibration would have to be qualified again.

    How a run works

    The same order every time. Only the drawing changes.

    1Read the drawing

    Muse Spark vision turns the schematic image into parts and connections. A person confirms the reading. The model gets this drawing and the shared bench description, nothing else.

    2Choose an experiment

    Muse Spark picks from a fixed menu of steps and sines, with or without a 9.99 kΩ load, and says why. The runner never picks for it.

    3Forecast first

    Every explanation still standing predicts the next measurement. The forecast is hashed before the board is touched.

    4Measure and cross out

    The Arduino UNO R4 fixture measures the real circuit. Explanations that miss by more than 9 mV, on the whole step or any region of it, are ruled out. If none survive, Spark may propose a part the drawing does not show.

    5Check on held-back inputs

    The final forecast is pushed to GitHub, then two reserved inputs that were never used for fitting are measured.

    6One reading at the bench

    When two explanations give the same waveforms, Spark names one part to read. Its expected range under each explanation is frozen first; the operator types one value; the same rule rules out.

    7Open the seal

    The hidden fault, committed as a digest before the first measurement, is opened; code checks the digest against that commitment, and the verdict is printed beside it. SAM 3.1 outlines the bodies in the board photo; Spark vision points at the part.

    Meta models

    Muse Spark 1.3 (agent and vision) through the Meta Model API for every experiment choice, structure proposal, schematic read and body call; SAM 3.1 for every board segmentation. 101 Spark calls and 6 SAM calls across the five cases, about $1.01.

    What is new

    The model is not asked to explain a measurement someone made. It chooses the measurement; the forecast is frozen first and code checks it against the measurement; the fault it was never told stays sealed until the verdict. The experiments did not exist until the model asked for them.

    What is not claimed

    Five completed cases are not an accuracy rate. Failed and abstained attempts are kept in the public ledger and named on the reports. Restored reruns show "no mismatch in the tests Spark chose", not a proof that every part is correct. The cases were known to the developers; this is not a blind test.

    Which model did what

    Muse Spark 1.3 vision
    Reads the schematic into parts and connections. After the diagnosis, names which SAM body is the part to read (01, 03, 05), or says it cannot tell (02).
    Muse Spark 1.3 agent
    Chooses every experiment and says why; asks for rewiring and for the check; proposes a part the drawing lacks when every value fails (04, 05); chooses what to read.
    SAM 3.1
    Segments the board photo after the diagnosis. Its native masks are the only outlines shown; no value is ever read from a photo.
    Fit engine, ngspice
    Simulates every explanation, forecasts, scores by RMS miss, freezes and publishes before each scored measurement.
    Bench, Arduino UNO R4
    Drives IN, records IN, OUT and REF; a reference guard stops the run when the bench itself drifts.
    Operator
    Builds the sealed fault, moves one jumper and reads one part when asked, never tells the model what is wrong.
